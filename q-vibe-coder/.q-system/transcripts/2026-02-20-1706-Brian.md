### Bug Report - Course Pills Don't Show Feeds
Brian reported: In the community section, the Town Hall works but enrolled course pills do not show feeds when clicked.

### Investigation - Root Cause Analysis
1. Signed in as Alex Sanders, navigated to My Communities > The Physics Lab
2. Confirmed Town Hall feed displayed correctly with posts
3. Clicked "Node.js Backend Development" pill — feed did NOT change (still showed Town Hall posts)
4. Traced the code path:
   - Sidebar.js `handleCommunitySelect()` routes creator communities to `onViewCommunityDirect` (line 307-311)
   - This navigates to **BrowseView.js** (the Discover-style creator profile), NOT to CommunityHub.js
   - BrowseView.js had course pills that were completely non-functional:
     - No onClick handlers on course pill buttons (lines 291-299)
     - No state for tracking which pill is selected
     - Hardcoded 3-post feed (`creatorPosts`) that never changed regardless of pill selection
5. Also discovered a secondary issue: fakePosts use hardcoded courseIds (1, 2, 3...) but Supabase replaces all course IDs at runtime (`coursesDatabase.length = 0` at database.js:1684), causing ID mismatches

### Fix Implementation - BrowseView.js
1. **Added import:** `import { fakePosts } from '../data/communityPosts'`
2. **Added state:** `selectedFeedCourse` (null = Town Hall, or `{ id, title }`)
3. **Made pills interactive:** Added onClick handlers and dynamic selected styling
4. **Replaced static feed with dynamic filtering:**
   - Town Hall pill: Shows hardcoded creator posts + creator-specific town hall posts from fakePosts (matched by `instructorId`)
   - Course pill: Filters fakePosts by matching `post.community === course.title` (title-based matching avoids the Supabase ID mismatch)
5. **Added empty state:** Shows "No posts yet" message when a course has no matching posts
6. **Added avatar support:** Course posts from fakePosts now show author avatars instead of just initials

### First Test - Wrong Posts Shown
